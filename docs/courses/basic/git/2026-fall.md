## 课堂讲义

### 1. 三个位置分别保存什么

| 位置 | 含义 | 查看方式 |
| --- | --- | --- |
| 工作目录 | 当前正在编辑的文件 | 打开编辑器或文件夹 |
| 暂存区 | 准备进入下一次提交的修改 | `git diff --staged` |
| 提交记录 | 已经保存的项目版本 | `git log --oneline` |

修改文件后，先查看差异，再选择本次要保存的文件，最后提交。一条提交应该表达一个清楚的小改动。

### 2. 创建独立练习项目

下载上方练习包并解压，**在解压后的练习文件夹中**打开终端。不要在已有课程作业或其他项目目录里运行初始化命令。

```powershell
git init -b main
git config user.name "你的名字"
git config user.email "你的邮箱"
git status
```

这两个 `git config` 命令只配置当前练习仓库。填写自己希望显示在提交记录中的署名和邮箱。

### 3. 保存第一次提交

先阅读 README 和 `.gitignore`，再记录练习文件：

```powershell
git add README.md hello.py .gitignore
git diff --staged
git commit -m "Add practice project"
git log --oneline
```

检查暂存差异时，应只看到自己计划提交的文件。`.gitignore` 中列出的生成文件不会被自动加入。

### 4. 用分支完成一个改动

新建分支，修改 README 中的学习目标，然后记录这次修改：

```powershell
git switch -c docs/learning-goal
```

用编辑器修改并保存 README 后，再运行：

```powershell
git diff
git add README.md
git commit -m "Document my learning goal"
git switch main
git merge docs/learning-goal
git status
```

`git status` 应显示没有待提交修改，提交记录中应包含两次提交。这次练习只操作自己的本地练习目录。

### 5. 认识 Pull Request

多人维护项目时，通常先把分支推送到远程仓库，再发起 Pull Request，说明改了什么、为什么改，以及如何检查。维护者审核后合并，项目就有了新的版本。

本课程网站也按这种方式整理资料。在线操作可参考 [GitHub 官方 Hello World 教程](https://docs.github.com/en/get-started/start-your-journey/hello-world)。

## 课后练习

1. 为练习项目写一段使用说明，并用单独提交保存。
2. 用 `git log --oneline` 找到这次提交，解释它和前一次提交有什么区别。
3. 用自己的话说明：为什么修改文件后，还需要 `git add` 和 `git commit`？

本示例不设置线上作业提交入口，实际课程的提交方式由讲师另行公布。

## 常见问题

??? question "为什么 Git 提示需要 user.name 和 user.email？"
    提交记录需要署名信息。在当前练习目录中完成上面的本地配置，再重新提交即可。

??? question "为什么修改过的文件没有进入提交？"
    先运行 `git status`。普通提交保存暂存区中的修改，确认该文件经过 `git add`，再查看 `git diff --staged`。
